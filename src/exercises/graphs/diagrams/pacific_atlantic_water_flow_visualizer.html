// Use 2D boolean matrices instead of HashSet<int[]>!
boolean[][] pac = new boolean[rows][cols];
boolean[][] atl = new boolean[rows][cols];
// 1. Seed Top (Pac) & Bottom (Atl) Borders
for (c...) { dfs(0, c, pac, heights[0][c]); dfs(rows-1, c, atl, ...); }
// 2. Seed Left (Pac) & Right (Atl) Borders

// 3. Overlap Check: Both pac && atl == true

void dfs(r, c, visited, prevHeight, heights) {
if (outOfBounds || visited[r][c] || heights[r][c] < prevHeight)
return; // DOWNHILL STEP REJECTED!
visited[r][c] = true; // Mark ocean reachable
dfs(r + 1, c, visited, heights[r][c], heights); // Down
dfs(r - 1, c, visited, heights[r][c], heights); // Up
dfs(r, c + 1, visited, heights[r][c], heights); // Right
dfs(r, c - 1, visited, heights[r][c], heights); // Left
}

Uncertainty Spotlight: Key Logic

Why Uphill (`heights[r][c] ≥ prevHeight`)? We trace paths starting FROM the ocean and walking inland. Water flows downhill ($\text{High} \rightarrow \text{Low}$). Walking backwards means we can only step UPHILL ($\text{Low} \rightarrow \text{High}$).
